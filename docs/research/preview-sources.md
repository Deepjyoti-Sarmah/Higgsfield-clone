# Preview media sources (T-030)

Every preset preview in the product is **generated by this repository** and stored in our own
Cloudflare R2 bucket. No higgsfield.ai, cloudfront.net or third-party media is served.

## Pipeline
1. **Source stills are our own FLUX.1-schnell generations** (`apps/api/app/adapters/fixtures/preview_sources/source-0N.jpg`,
   1024x1024), produced by our own deployed Modal endpoint (`apps/gpu/flux_image.py`,
   `higgsfield-flux-image` app) — not photographed, not a third-party stock/Unsplash image, so
   there is no licence obligation and nothing to attribute. Prompts were chosen for strong depth,
   texture and leading lines so the camera-move recipes read clearly:
   - `source-01.jpg`: "a neon-lit tokyo alley at night, dense signage, deep one-point perspective, strong leading lines, cinematic"
   - `source-02.jpg`: "a windswept desert canyon at golden hour, layered rock strata, deep atmospheric perspective, strong texture"
   - `source-03.jpg`: "a portrait of a person against a raw textured concrete wall, dramatic side light, shallow depth of field" (a synthetic FLUX face, not a real person)
   - `source-04.jpg`: "a misty forest path at dawn, tall trees receding into fog, strong leading lines, soft volumetric light"
   - Superseded: the original brief's ffmpeg-gradient fallback (`make_sources.sh`, still in the repo
     for offline/CI use) produced flat teal/navy/brown/magenta rectangles with no real imagery —
     replaced once a real, licence-clean generator (our own FLUX endpoint) was live.
2. `scripts/build-preset-previews` runs the **existing** `LocalMotionAdapter` recipe for each of the
   12 catalog presets (5 s, 720p, h264 + faststart) and extracts poster frames.
3. The script uploads `previews/<slug>.mp4` and `previews/<slug>.jpg` through `S3ObjectStorage`,
   so it targets MinIO locally and R2 in production with the same `S3_*` env names.
4. Four posters are committed to `apps/web/public/showcase/sample-0N.jpg` as same-origin stills for
   the create-image idle showcase and the create-video "Add image" step illustration.

## Where the media is referenced
| Surface | Asset |
|---|---|
| Explore gallery cards | `GET /api/v1/presets` -> `preview_url` -> `previews/<slug>.mp4` |
| Create-video preset picker | same API field |
| Explore hero video cards | `apps/web/src/api/webMedia.ts` -> `previews/<slug>.mp4` |
| Create-video "how it works" tiles | `webMedia.ts` -> `previews/<slug>.mp4` |
| Create-image idle showcase | `/showcase/sample-0N.jpg` (repo, from the posters above) |

## Regenerating
```
# preferred: real stills from our own FLUX endpoint (see prompts above), saved as
# apps/api/app/adapters/fixtures/preview_sources/source-0N.jpg
# fallback (offline/CI, no GPU): bash apps/api/app/adapters/fixtures/preview_sources/make_sources.sh

scripts/build-preset-previews --dry-run    # local render only
scripts/build-preset-previews              # render + upload to S3_* storage
```
